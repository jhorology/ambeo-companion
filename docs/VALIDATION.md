# レビュー修正の検証（2026-10-01）

指摘の背景と各修正の対応内容は [コードレビューと修正対応](CODE_REVIEW_2026-10-01.md) を参照。

## 修正

- Fallback は現在の物理フォーマットを取得でき、Atmos／マルチチャンネルではない場合にだけ適用する。
- 初回取得に失敗した音量エンドポイントは、操作情報が必要になった際に再取得する。単一オブジェクトと配列の両方を受け付ける。
- 通常のアプリ終了は `applicationShouldTerminate` の `.terminateLater` でブースト解除の完了を待つ。解除には実機の最新音量を使う。
- ブースト適用量を機器 UUID ごとに保存する。解除が失敗した場合は記録を保持し、同じ機器への再接続時に二重加算を防ぐ。別の機器へ切り替える際は旧機器の解除を試みる。

## 実行方法

```sh
swift test
# 実機接続を含む。音量を1段だけ下げて検証し、元の値へ戻す。
AMBEO_INTEGRATION=1 swift test
```

通常実行では実機テスト2件をスキップする。統合テストでは `http://ambeo.local` を使う。

## 結果

統合テスト7件がすべて成功した。テストのビルドにはアプリ本体も含まれる。

| 検証内容 | 方法 | 結果 |
| --- | --- | --- |
| 初回取得失敗から操作情報を再取得 | モック、単一／配列レスポンス | 成功 |
| 初回接続失敗後に実機から音量と min/max/step を再取得 | 初回だけ通信エラーを注入し、その後は実機へ HTTP 接続 | 成功 |
| ブースト記録の再読み込みと機器 UUID ごとの分離 | 独立した UserDefaults suite | 成功 |
| 最新音量を使った解除と音量下限の保護 | モックの本体音量をキャッシュ取得後に変更 | 成功 |
| Atmos／マルチチャンネル判定 | 実機で観測済みの cc+3、8ch PCM、2ch PCM | 成功 |
| 実機音量の変更、別クライアントからの確認、ブースト解除、復元 | HTTP API。音量25 → 24 → 25 → 24 → 25 | 成功 |

最後に HTTP API で音量25への復元を再確認した。ミュート、プリセット、スタンバイ設定は変更していない。

## 実機で未確認の範囲

実機の decoderAudioFormat は空だったため、Atmos 再生中の CoreAudio フォーマット維持は未確認。2台の実機間の切り替え、ブースト適用中の GUI アプリ終了／再起動も未確認。これらについて上表の判定・保存・解除処理のテストを、実機での操作確認の代わりに扱わない。

強制終了時は非同期の解除を実行できない。保存済み記録は再接続時の復旧に使うが、HTTP 操作の成立と記録保存の間でプロセスが終了するケースは保証できない。
